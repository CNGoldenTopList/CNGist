# 数据模型与业务语义

PostgreSQL 是运行时唯一主数据源。结构以 `backend/src/db/schema/` 和 `backend/drizzle/` 中的迁移 为准；外部快照、表格和离线文件不能作为运行时回退。

## 主键与业务标识

所有业务表都有数字 `id`：PostgreSQL `integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`。账户、身份、会话、目录、记录、标签、关系、设备、缓存及任务均遵循此规则。原有自然键和组合键保留唯一约束，新增数字主键不会允许重复关系。

API 中实体 ID 使用 JSON number，范围 1–2147483647，路径参数使用十进制整数。排序、预览和失败事务可能留下空号；ID 不是业务序号，不能靠连续性推断数据缺失。

Tier `code`、游戏 `sid`、B 站 UID、OSS `objectKey` 是业务标识，保留字符串。设备表的 `external_id` 保留对外 UUID；Mod 配置与授权兑换返回这个协议标识，设备管理接口返回内部数字 `id`。`datasetId`、`historyEpoch`、`streamEpoch`、`connectionId`、`mutationId` 也是同步标识，不是实体主键。Cookie、设备令牌和授权码继续采用随机凭据。

`migration_id_map(entity,old_id,new_id)` 保存旧新主键映射。旧链接和旧客户端使用的业务 ID 必须转换后才能访问新接口。

## 目录与 Tier

- 所有地图引用地图包；无归属地图也用单地图包呈现。
- `challenge.scope='map'` 只引用 `map_id`，`scope='campaign'` 只引用 `campaign_id`，父级互斥。应用层分别映射为 `Challenge` 与 `MultiMapChallenge`。
- `deleted_at` 是软删除；回收的实体及其子对象不参与公开目录或统计。
- 大厅属于地图包，地图只加入同包的一个大厅。根级排序使用 `map:<id>`、`hall:<id>`；菜单保存固定包和默认收藏包。
- 正式中文名仅来自正式数据或用户对照。搜索兼容英文、中文、全拼、首字母及中拼混输。

正式 Tier 从难到易：

```text
t-1
h0 m0 l0
h1 m1 l1
h2 m2 l2
h3 m3 l3
t4 t5 t6 t7
```

排序使用 `tier.rank`。Standard 具体保存为 `high-std`、`mid-std`、`low-std`，均非正式档位，排在 T7 后；`undetermined` 表示未定档，不能混为 Standard 或默认 T7。主榜不含 Standard 与未定档，正式 Tier 个人统计保持原口径。

Hist 是地图评级，保存 `hist_stars/hist_sub_tier`：null/null 无评级，0/null 未定档，1–5 星必须指定 lower/upper。同图挑战共享 Hist，地图包级挑战不借用地图评级。

## 记录与挑战 DAG

普通提交引用已存在的挑战；新挑战提案暂时不引用挑战，必须有 `proposed_target`。玩家身份只能取会话认领关系。已有 Standard 挑战的普通提交或重新提交直接 accepted，不伪造审核者或审核时间；新挑战提案默认需审核。受信任的服务端导入可对严格匹配 goldberries.net Golden Berry / Silver Berry 且来源 Tier 1/2/3 的新提案自动建档为 low/mid/high-std，并按 Standard 规则自动通过；审核者和审核时间仍留空，审计记录注明发起者与来源，不表示人工验片。该路径保留其他标签及同图其他记录。

玩家记录 `submission.verified` 为非空布尔值，默认 false；挑战本身没有此字段。正式 Tier 记录经管理员通过后设为 true；Standard 普通提交、新挑战归档及来源导入建档均不新增此标记。迁移将当时所有正式 Tier 挑战下的已有记录标为 true（不改变原状态）。Tier 降为 Standard 保留 verified；Standard 升为正式 Tier 时，其所有 verified=false 的记录转为 pending，保留标签、软删除及审核历史，清除审核中认领；单条、批量调档与拆分/合并移动遵循同一规则。玩家修改后重投会清除 verified，重新走审核。客户端不能直接设置 verified。

同一玩家、同一挑战可有多条记录。公开统计只计 accepted 且未软删除、未 Hidden 的记录，并排除回收玩家和目标。挑战列表保留有效录像，通关人数按玩家去重；个人成绩按玩家与挑战选最近达成的记录，未知日期排后，同日优先最近审核，再按 ID 稳定选择。不混合不同记录的标签、录像或意见。

DAG 边从较严格挑战指向被其涵盖的挑战，只允许同一地图内关系，禁止自环与环。显式保存的边优先；没有自定义关系时使用共享规则生成默认链。继承与个人成绩去重使用同一投影：弱挑战已有有效记录时，较强挑战的成绩可涵盖它；互不涵盖的成绩保留。地图包级挑战不参与地图 DAG。

Rejected 是审核结论，记录保留。本人可修改 pending/rejected 记录后重新提交，不能将普通记录转换为提案。撤回任意状态的本人记录进入回收站。玩家回收期间保留记录原状态，恢复玩家不会改变记录的隐藏或软删除状态。

## 名称与标签

- `[No DTS]`、`[No Major Skips]` 等限定保留在挑战名中。末尾 FC 与 [FC] 通过共享显示函数统一展示，不改写原始名称。
- `description`/地图包 `blurb` 是介绍，`notice` 是注意事项，不互相覆盖。
- `RAW` 不能出现在公开标签中。明确 FC 挑战可补 FC，C/FC 不可；FC、月莓、moon 同义去重并保留配置的标签文字。
- No Major Skips 可按挑战限定补标；DTS 只来自记录配置，不能由名称推断。
- 标签分 mark（流程）、badge（颜色）、note（说明）；预设、规范化和颜色规则在 `shared/src/review-tags.ts`，颜色只接受 `#rrggbb`，不借用 Tier 色。
- Golden/Silver/Berry 编号是地图内分段，按编号排序，不参与地图代表难度计算。

## 账户与玩家

账户角色为 player/admin/super_admin。两档管理员共享日常管理权限，管理员任免与回收站最终确认只允许有效超级管理员；任免接口只允许 player 与 admin 互转。身份、密码摘要、会话、邮箱令牌与玩家档案分开存储，账户邮箱不作为 OIDC 身份键。

`player.bilibili_uids` 是有序且去重的 B 站 UID 列表；旧单 UID/主页字段同步首项。名称占用、UID 占用都检查回收档案和相关待审申请。账户认领不接受客户端自报身份。

新玩家默认 unasked，只表示联系进度。回收玩家同时解除账户认领，保留登录账户和登录方式；恢复档案不会恢复认领。最终确认移除回收站项并保留软删除档案。

头像是派生缓存，从档案 UID 查询后上传 OSS，仅保存对象索引。正常缓存 7 天，自动失败退避 5 分钟，本人手动刷新至少间隔 1 分钟；无图由前端显示名字首字。所有封面与反馈图片也只保存 OSS 索引，读时生成 CDN URL。

## 管理与社区

管理命令和审计在同一事务内；`backend/src/modules/admin/audit.ts` 的 `writeAudit` 是审计写入口。目录批量创建/修改属于鉴权 API；数据库迁移、恢复和离线维护需要服务器权限，网站管理员身份不授予数据库凭据。

意见的作者与当前 Tier 快照由服务端确定。同一意见每账户最多一份回复，撤票保留评论。挑战意见默认 7 天期限，一般建议不设期限；截止与最终决定在事务内检查。完成状态由当前认领玩家的有效记录和 DAG 计算，不能由客户端声明。历史匿名回复不按显示名认领。

问答分 rules/general，两组分别排序，英文空值回退中文。意见和问答删除采用各自的管理事务及审计，不使用回收站。反馈附件属于上传账户，提交时核验归属与数量。

## 设备同步

设备授权使用随机授权码及 PKCE S256。每次上传检查账户有效性、设备撤销和同步开关；账户与设备身份从 Bearer token 取得，忽略请求体身份。历史清空会轮换 historyEpoch 并关闭导入，避免旧队列复活。

CCT 保存有界最新状态：每房最多 100 次尝试，不保存无限事件历史。设备/数据集/SID/面/segment 隔离；revision/hash 比较后交换，最后一次 mutation 支持 ACK 重试。路线元数据只作显示和搜索线索，不能成为目录权威。

地图统计的 totalDeaths 按最大值合并，noGoldenBestDeaths 按最小值合并，completed 为 true/false/null 且 true 不被 false 回退；未知值不覆盖已知。不同设备/存档统计不相加，读取取最近有效一份。统计不写挑战成绩、DAG 或愿望单手填字段。

SID/面配对须经管理员审核，同一 SID/面仅一条 approved 目标；目标必须是地图。Overlay 仅返回已配对的有效地图、地图包和地图挑战，不返回账户、设备或私人统计。

Presence 每设备保存最新快照，connectionId/sequence/batchHash 保证重复心跳不重复处理。60 秒超时视作离线。公开在线列表只返回约定的玩家活动摘要，私人统计仅本人可读。保存开关、设备撤销和 historyEpoch 共同控制可见性。

带金房间规则与短期事件队列继续保存，心跳在事务内产生事件。独立 QQ 机器人使用数字 ID 消费队列，发送前复查权限、软删除与事件时效；后端不会自行启动机器人。详细设备请求与容量限制见 [API 文档](../backend/docs/api.md)。

第九章专页根据已审核的 `Celeste/9-Farewell` 配对定位地图，合并普通及限定 C/FC 投影，每玩家取最早的有效记录；未知日期排后，标签与录像取同一条记录。
