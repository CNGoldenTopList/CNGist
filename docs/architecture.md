# 架构

## 模块边界

`backend/src/app.ts` 组装 Fastify，`routes.ts` 登记路由，`server.ts` 负责进程启动与退出。路由接收 HTTP 请求，业务服务负责校验和数据库事务，Drizzle schema 只描述表与约束。

业务模块包括账户认证、目录、玩家、记录、意见、反馈、愿望单、问答、设备同步、图片和管理公共逻辑。管理员对目录的操作放在目录模块，对玩家的操作放在玩家模块；管理公共模块只保留审计、事务、待办和回收站等职责。

`shared/` 只包含不依赖数据库、Fastify 或浏览器框架的类型与纯函数。前端通过 HTTP API 获取数据，可复用共享的名称、搜索、Tier 与 DAG 规则。

## 请求与权限

会话 Cookie 和设备 Bearer token 都只在数据库保存摘要。网站请求根据有效会话反查账户，管理权限每次读取当前角色；设备请求根据令牌反查账户、设备、撤销状态和同步开关。客户端提交的账户 ID、玩家 ID 或角色不构成权限。

每次请求使用独立的 AsyncLocalStorage 上下文，包含当前请求、响应和本次请求的目录缓存。并发请求不共享账户或目录快照。后台任务不得依赖已结束的 HTTP 上下文。

写请求检查 Origin 与跨站请求标记；登录类接口限流。前端和 API 使用同源部署，未开放跨站 Cookie 接入。

## 写入与读取

一次管理命令对应一个事务；失败结果也会触发回滚，审计与业务数据一起提交。批量目录接口默认预览，通过事务回滚返回拟执行结果；显式 `dryRun:false` 才提交。预览消耗的自增号允许空缺，不能把预览 ID 当作最终 ID。

公开目录从 PostgreSQL 读取并过滤回收、隐藏记录及失效父级；挑战通关人数与个人成绩经 DAG 投影计算。管理员读取使用单独的鉴权接口，不能把管理数据混入公开目录。

## 数据库与任务

一个初始 SQL 完成所有业务表、索引、约束及 Tier 初始化。旧库转换是独立脚本，采用只读源事务和新库写事务，映射表保留旧 ID 到新 ID 的关系。

本地备份由独立进程执行，systemd timer 定时启动；不在 HTTP 进程里运行常驻定时器。图片上传至 OSS，CDN 地址在读时由对象 key 生成。

公开仓库提供构建与启动命令及同源路由要求，进程管理器、代理配置与定时任务由部署者维护。QQ 机器人独立启动，仅依赖共享业务规则与后端数据。
