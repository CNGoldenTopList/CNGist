# CN 金榜

CN Celeste 社区金榜独立站。此目录是项目 Git 仓库，使用 npm workspaces 管理后端与共享代码。

后端使用 Fastify + Drizzle + PostgreSQL，前端使用 Vue 3 + Vite + Naive UI。生产部署见 [部署说明](docs/deployment.md)。

## 目录

```text
frontend/                 Vue 前端
backend/
  src/
    modules/              按业务域组织路由、服务与命令
    db/schema/            按业务域拆分的 Drizzle 表定义
    config/               根目录 JSON 配置读取
    plugins/              HTTP 请求上下文
    integrations/         OSS、邮件、B 站等外部服务
    jobs/                 独立后台任务
  drizzle/                增量 SQL 迁移 + Drizzle 元数据
  scripts/db/             迁移、校验、导入、恢复
  docs/api.md             API 文档
  tests/                  少量关键边界测试
shared/src/               纯类型、校验、搜索、Tier、DAG 等共享规则
docs/                    数据语义、架构、运行维护
qqbot/                   QQ 群业务指令与消息服务
integrations/             后端与机器人共用的来源缓存
config.example.json       按功能分组的配置示例
config.json               本机配置，不提交
backups/                  本地数据库备份，不提交
```

## 启动后端

需要 Node.js 22+（本次验证为 24）、npm 和 PostgreSQL 16+。先创建独立数据库及其拥有者，再执行：

```bash
npm install
cp config.example.json config.json
# 编辑 config.json，database.url 指向新库
npm run db:migrate
npm run db:check
npm run dev
```

默认监听 `127.0.0.1:8268`。健康检查为 `/health`，公开功能配置为 `/api/config`，接口文档为 `/api/reference.md`。

生产构建及启动：

```bash
npm run build
npm start
npm run build:frontend
```

配置只从仓库根目录 `config.json` 读取，不使用 `.env`。生产配置文件权限建议为 `600`。`server.origin` 填浏览器实际访问的站点源地址；反向代理时，`trustProxy` 仅配置可信代理 IP。前后端通过同一个站点源访问 API。

首页底部网站信息区通过 `/api/config` 自动获取：`site.developers` 配置开发者数组（`name` 显示名、`playerId` 本站玩家 ID，链接到个人页），`site.sponsorship` 配置赞助与域名署名；省略时隐藏对应项。网站管理员从数据库动态列出所有有效普通管理员（不含超级管理员），已认领有效玩家档案的名字链接到个人页。

首页底部还支持 `site.donation: { "label": "渠道名称", "url": "https://…" }`（捐赠渠道）与 `site.sourceUrl: "https://…"`（开源地址，仅链接）。链接仅接受 HTTP(S)；不配置时隐藏对应项，开源地址也可设为空字符串。修改配置后重启后端生效。

备案号由 `config.json` 的 `site.icpNumber` 配置（例如 `沪ICP备2024102702号-2`），留空或省略时不显示；链接固定指向工信部备案查询网站。修改配置后重启后端生效。

可选功能未配置时，对应能力不可用：`auth.oidc` 为水鱼 OIDC 参数，`mail` 为 SMTP 参数，`oss` 为阿里云 OSS 与 CDN 参数；字段见 [配置类型](backend/src/config/index.ts)。前端通过 `/api/config` 获取可用登录方式和邮件开关，不接触凭据。

## 数据与迁移

所有 46 张业务表使用 `integer GENERATED BY DEFAULT AS IDENTITY` 主键，JSON 中的实体 ID 为数字。Tier code、B 站 UID、游戏 SID 和同步协议标识继续表达各自的业务含义。设备对外 UUID 与内部数字主键分开，详见 [数据模型](docs/data-model.md)。

金榜速录专用授权需先执行 `npm run db:migrate` 应用 `0004_submission_token.sql`，再部署前后端，最后发布 CNGoldenClip 1.1.1。管理员直接访问 `/admin/submission_token`，点击「一键授权」才签发并写入本机油猴，之后无需常驻连接页。每次添加前插件向 `/api/clip/authorization` 验证 token。无需开放 CORS 或修改网站登录 Cookie。

`backend/drizzle/0000_initial.sql` 包含完整表结构、约束与 Tier 字典，只用于初始化新库。`meta/` 保存 Drizzle 的结构快照与日志。后续结构变化使用新增迁移；`0001_submission_verified.sql` 为记录增加验片标记并回填已有正式 Tier 记录。

旧库的数据转换使用 [新库迁移流程](docs/operations/migration.md)，包含默认回滚的预览、旧新 ID 映射及引用校验。不要对现有线上库执行初始迁移。正式切换前冻结旧库写入，并完成独立新库的数据与引用校验。

图片统一通过 OSS/CDN 提供，数据库保存对象 key 和元数据。封面编辑先调用图片上传接口，再保存返回的 `objectKey`，不保存本地 public 路径。

## 验证与备份

```bash
npm install
npm run build
npm test
npm run db:check
```

接口测试会清空测试库，配置中的数据库名必须以 `cngist_refactor_check_` 或 `cngist_refactor_test_` 开头，并且必须是专用临时库。迁移测试使用独立内存 PostgreSQL。测试只覆盖鉴权、事务、记录投影和迁移等关键边界，不追求覆盖率。

```bash
npm run backup
npm run db:restore -- /绝对路径/postgres.dump
```

备份默认按北京时间保留最近 7 个自然日、4 个自然周（周一开始）、12 个自然月各最新一份，重叠去重，最多 23 份。恢复只接受空数据库，执行前更改 `config.json` 的目标库。备份与恢复说明见 [运维说明](docs/operations/migration.md#备份与恢复)。

## 项目约定

- 保持页面克制、高信息密度和深色查询工具的定位。
- 蓝色表示交互，暖金色表示品牌，Tier 色只表达难度。
- 中文名仅采用正式数据或用户提供的对照；不自行翻译。
- 每张地图属于地图包；地图挑战和地图包级多地图挑战保持独立作用域。
- 代码按业务职责组织，注释简短；前端不引用后端模块。
